# Carry On Only — План реализации

> «One bag, nothing extra.»
> Сборы в поездку под лимит ручной клади: сколько каждой вещи брать с учётом
> погоды по дням, планов и стирок, что надеть на себя в дорогу, что урезать,
> если не влезает, — и чему научиться после поездки.

---

## 0. Архитектурные решения

- Полностью локальное: `expo-sqlite`, без бэкенда и уведомлений; `INTERNET` и
  `POST_NOTIFICATIONS` заблокированы, нужна только вибрация.
- Тема всегда light: «кожа чемодана» `#7A4529` на льне `#F7F4EE`, бирка — горчичный.
- Все обращения к БД — через мьютекс; укладка (ДП) считается сразу, конфликты —
  после отрисовки. «Назад» без истории ведёт на главный.
- Стартовый гардероб добавляется только по нажатию.

## 1. Движок (`src/lib`)

1. **`need.ts`** — где вещь нужна (погода, занятие), циклы между стирками,
   количество = max по циклам ⌈расход / дней носки⌉; дни-нехватки при меньшем числе.
2. **`model.ts`** — накапливаемый множитель «дней носки» по каждой вещи из разборов
   (log(план/надето), забывание ×0.7, априор силой 2 поездки), частичное
   объединение с видом вещи; пересборка из журнала.
3. **`pack.ts`** — идеальный список; на себя — самая тяжёлая нужная вещь в каждом
   слоте (обувь / верх / одежда); если тяжелее лимита — рюкзак с множественным
   выбором (0..идеал штук каждой вещи), цена — дни-нехватки × важность (не
   стирающиеся вещи дороже, обязательные — ещё дороже), точное ДП по весу шагом
   25 г с округлением вверх. Тест сверяет с полным перебором.
4. **`changes.ts` / `conflicts.ts`** — стирка в день, лимит сумки, без занятия,
   оставить вещь; перевес / не влезают обязательные / длинный отрезок без стирки;
   выходы проверены пересчётом и ранжированы.
5. **`history.ts`** — доля надетого, лишний вес по поездкам, редко надеваемое.

## 2. Модель данных

| Таблица | Поля |
|---|---|
| items | id, name, kind, grams, per_day, wears, weather, activity, essential, slot, created_at |
| trips | id, name, start, days (JSON: погода, занятия, стирка), limit_g, bag_g, skip, closed, created_at |
| packed | trip_id, item_id |
| usages | trip_id, item_id, packed, used, planned |
| meta | model, modelVersion, haptics |

## 3. Экраны (6)

1. **Home** (Segmented Pills Top) — Next trip / Trips / Wardrobe; hero `BagGauge`,
   полоса дней (тап — погода, удержание — стирка), самые тяжёлые вещи; снизу
   прилипшая кнопка действия.
2. **Trip** — дни, вес по видам, конфликты с выходами, чек-лист по группам с липкими
   заголовками, «почему столько» удержанием, разбор после начала поездки.
3. **Debrief** — сколько надел каждой вещи, живое превью изменения множителей.
4. **What if** — стирка / сумка / без занятия: Now → If и изменившиеся вещи, Apply.
5. **Item** — инлайн-правка, выученный множитель с объяснением, история по поездкам.
6. **Stats** — 7 секций, тап по поездке перестраивает долю надетого и «неношеное».
